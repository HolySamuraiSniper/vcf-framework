# /vcf-framework:forensics — Post-mortem for failed loops

**Goal:** When a vcf-framework loop fails or has to be abandoned mid-way, capture what went wrong **before** you discard the work. The next loop starts ahead if this one's failure is documented.

This skill is read-only investigation. It does NOT modify source code or `.vcf/<slug>/` state files (other than writing the forensics report itself).

## Argument

Takes one argument: `<feature-slug>` (must match an existing `.vcf/<slug>/` directory).

## Prereqs

- `<cwd>/.vcf/<feature-slug>/STATUS.md` must exist (any state — built, audited, halted, or otherwise).

If missing, **halt** — there's nothing to investigate.

## Data sources

Read everything in parallel:

- `git log --since=<loop-start-timestamp>` (start timestamp from STATUS.md)
- `git status` / `git diff` (uncommitted work, conflicts)
- `<cwd>/.vcf/<feature-slug>/STATUS.md` (current position, step log)
- `<cwd>/.vcf/<feature-slug>/PRD.md` (acceptance criteria — the original target)
- `<cwd>/.vcf/<feature-slug>/PLAN.md` (intended slice breakdown)
- `<cwd>/.vcf/<feature-slug>/BUILD-NOTES.md` (what was actually built per slice)
- `<cwd>/.vcf/<feature-slug>/REVIEW-slice-*.md` (per-slice findings)
- `<cwd>/.vcf/<feature-slug>/FINAL-REVIEW.md` if it exists (what final-audit caught)
- `<cwd>/.vcf/<feature-slug>/VERIFY.md` if it exists (goal-backward gap analysis)
- `<cwd>/.vcf/<feature-slug>/SELF-EVAL.md` if it exists

## Anomaly types to check

At least 4:

1. **Stuck loop** — Same step appears in step log more than 3 times. Why couldn't the user progress?
2. **Missing artifacts** — STATUS.md says a step completed but the expected artifact (PRD.md, PLAN.md, REVIEW-slice-N.md) doesn't exist or is empty.
3. **Abandoned work** — Step log has a recent entry but no commits in `git log` since that timestamp. User started but didn't finish.
4. **Crash / interruption** — STATUS.md shows in-progress state with no closeout. What was the last action?
5. **PRD-vs-code mismatch** — VERIFY.md or FINAL-REVIEW.md flagged acceptance criteria that the code doesn't actually deliver. Why did the build slice miss them?
6. **Scope drift** — Slices in PLAN.md don't match what was actually built in BUILD-NOTES.md. Where did scope expand or contract?

## Output

Write `<cwd>/.vcf/<feature-slug>/FORENSICS.md`:

```markdown
# Forensics: <feature-slug>

Generated by /vcf-framework:forensics at <ISO timestamp>.

## Loop summary

- Started: <ts from STATUS.md>
- Last activity: <most recent timestamp>
- Final state: <halted | abandoned | failed-final-audit | other>
- Slices planned: <N from PLAN.md>
- Slices built: <M from BUILD-NOTES.md>
- Slices audited: <K from REVIEW-slice-*.md count>

## Anomalies detected

### Stuck loop
- <description + evidence: which step, how many retries>

### Missing artifacts
- <description + evidence>

### Abandoned work
- <description + evidence>

### Crash / interruption
- <description + evidence>

### PRD-vs-code mismatch
- <description + evidence: which acceptance criteria + which slice should have delivered them>

### Scope drift
- <description + evidence>

## Root-cause hypothesis

<1-3 sentences>. Ground the hypothesis in specific evidence from the artifacts above — no speculation.

## What would have prevented this

<actionable change: scope smaller? different reviewer choice? more time in /vcf-framework:plan? different tier? Something else?>

## Recommendation

- [ ] Discard the loop entirely (rm -rf .vcf/<feature-slug>/, no further action)
- [ ] Resume from <step N> with the adjustments above
- [ ] Open a new loop with a tighter scope and reference this forensics report in :context
- [ ] Other: ...
```

## Discipline

- **Read-only.** Do not modify source code or other `.vcf/<slug>/` files during forensics.
- **Ground findings in evidence.** Every anomaly must cite a specific commit, file, or state-file line. No "I think maybe..." speculation.
- **No fabrication.** If data is insufficient to diagnose, say so explicitly — don't invent a root cause.
- **Redact sensitive data.** Strip absolute paths, API keys, tokens from the report if you'll share it.

## After this step

1. Append to STATUS.md: `- forensics complete at <timestamp> → see FORENSICS.md`. Update `**Current step:**` to `FORENSICS-INVESTIGATED`.
2. Present the recommendation to the user. Wait for their decision.
3. If the user chooses "discard the loop" or "resume from step N", they run the next command. Forensics doesn't auto-resume.
