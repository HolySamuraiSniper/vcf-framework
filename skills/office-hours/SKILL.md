# /vcf-framework:office-hours — Pre-brainstorm ideation

**Goal:** Loose conversation to flush out goals, constraints, and risks BEFORE `/vcf-framework:brainstorm` commits to specific alternative shapes.

This is the warm-up. If you already know the 2–3 shapes you want to compare, skip this and go straight to `:brainstorm`.

## Argument

Takes one argument: `<feature-slug>`. If no `.vcf/<feature-slug>/` exists yet, route to `/vcf-framework:context` first.

## Prereqs

- `<cwd>/.vcf/<feature-slug>/CONTEXT.md` must exist (output of `/vcf-framework:context`).

If missing, halt and route to `/vcf-framework:context`.

## Process

Open with the user's vague idea. Ask exploratory questions one at a time. Listen for:

### Goals

- What does success look like a month after this ships?
- What's the smallest thing that would count as "we shipped something useful"?
- What does this feature unlock for the user or business?

### Constraints

- What can't change about the surrounding system? (Schema, contracts, external integrations, deploy cadence.)
- What's the budget — engineer-hours, infrastructure cost, time-to-ship?
- What's already locked in via earlier ADRs that this feature must respect?

### Risks

- What's the worst plausible outcome if this goes wrong?
- Which assumption are you most uncertain about?
- What would a senior engineer push back on if they read your CONTEXT.md right now?

### Stakeholders

- Who cares about this shipping? Who'd notice if it didn't?
- Who'd be the first to flag a regression?

Take rough notes throughout. The point is **clarity**, not a polished doc.

## Output

Write `<cwd>/.vcf/<feature-slug>/IDEATION.md`:

```markdown
# Ideation: <feature-slug>

Generated by /vcf-framework:office-hours at <ISO timestamp>.

## Goals (as the user said them)

- ...

## Constraints surfaced

- ...

## Risks named

- ...

## Stakeholders

- ...

## Hard-to-falsify assumptions (probe these in /vcf-framework:brainstorm)

- ...

## Notes / open questions

- ...
```

## After this step

1. Append to STATUS.md: `- office-hours complete at <timestamp> → see IDEATION.md`. Update `**Current step:**` to `02 — /vcf-framework:brainstorm`.
2. Tell the user verbatim: "Ideation captured for `<feature-slug>`. Run `/clear` then `/vcf-framework:brainstorm <feature-slug>` to converge on 2–3 alternative shapes."

## Discipline

This is the **loose** step — resist the urge to lock in a chosen shape here. The brainstorm gate is where alternatives get compared and one is chosen. If office-hours produces a single obvious answer, that's signal the feature is Tier-1 or Tier-2 and you can skip both `:office-hours` and `:brainstorm`, going straight to `:prd`.
