# /vcf-framework:plan — Step 04: PRD → technical architecture

**Goal:** From "what" to "how", in enough detail that execution is mechanical.

This is Step 04 of 10 in VCF gate mode. For full doctrine, see `vcf-framework:overview`.

## Argument

Takes one argument: `<feature-slug>`.

## Prereqs

- `<cwd>/.vcf/<feature-slug>/PRD.md` must exist (output of `/vcf-framework:prd`).

If missing, **halt** and tell the user: "Missing `PRD.md` for `<feature-slug>`. Run `/clear` then `/vcf-framework:prd <feature-slug>` first." Do not proceed.

## Inputs to read

- `<cwd>/.vcf/<feature-slug>/PRD.md` — acceptance criteria + scope + success metrics
- `<cwd>/.vcf/<feature-slug>/design.md` — chosen shape + hard constraints
- `<cwd>/.vcf/<feature-slug>/CONTEXT.md` — prior decisions, files likely touched
- `<cwd>/.vcf/<feature-slug>/STATUS.md` — verify state and tier

## Process

**Use Plan Mode** (`EnterPlanMode` → present the plan → `ExitPlanMode`) for any work that:

- Touches >3 files, OR
- Crosses module boundaries (schema + API + UI), OR
- Matches the project's "Confirm approach before large changes" rule (CLAUDE.md / AGENTS.md).

Plan Mode is the canonical review-before-build gate — the harness restricts edits to read-only and surfaces your plan formally for approval via `ExitPlanMode`. Presenting a plan as inline text + an `AskUserQuestion` gate is a **weak substitute** — it skips the formal mode transition and doesn't enforce read-only.

For smaller structured plans, fall back to `superpowers:writing-plans`. For trivial single-file work, you can skip plan entirely and go straight to `/vcf-framework:build` (note the skip in STATUS.md).

## Output

After Plan Mode is approved (or for smaller plans), write `<cwd>/.vcf/<feature-slug>/PLAN.md`:

```markdown
# Plan: <feature-slug>

Generated by /vcf-framework:plan at <ISO timestamp>.

## File tree changes

### New files

- `path/to/new.ts` — <purpose>
- ...

### Modified files

- `path/to/existing.ts` — <what changes and why>
- ...

### Deleted files

- ...

## Module boundaries

| Module | Public interface | Consumers |
|---|---|---|
| ... | ... | ... |

## Data flow (non-trivial path)

```
<request entry point> → <handler> → <DAL function> → <DB>
                                  ↓
                              <observability span>
```

(Use a Mermaid diagram if the flow is more complex than a single chain.)

## Threat model

- **Trust boundaries:** <where untrusted input enters; how it's validated>
- **Tenancy boundaries:** <how cross-tenant data is prevented from leaking, if applicable>
- **Authn / authz:** <which checks run where>
- **Secrets handling:** <how credentials flow through the system>

## Phase breakdown (vertical slices)

Each slice must be end-to-end testable — DB → DAL → API → UI → test. NEVER horizontal layers ("all DB → all API → all UI") — that produces nothing testable until the end.

| # | Slice | Files | Blocks | Verification |
|---|---|---|---|---|
| 1 | <name> | <key files> | none | <how it proves itself> |
| 2 | <name> | <key files> | #1 | ... |
| 3 | <name> | <key files> | #2 | ... |

## Verification strategy

How each slice proves itself before the next starts:

- **Slice 1:** <test name + what it asserts + how to run it>
- **Slice 2:** ...

## Risks + mitigations

- <risk> — <mitigation>
- <risk> — <mitigation>
```

## Discipline

A plan that doesn't survive contact with the code is fine — adjust and continue. A plan you skipped because "it's obvious" is the one that bites.

**Vertical slices, not horizontal layers.** This is the most violated rule in plans. If your phase table looks like "Phase 1: all schemas / Phase 2: all DALs / Phase 3: all routes / Phase 4: all UI", restructure before you exit Plan Mode. Each phase should ship a thin slice that demonstrates the feature working end-to-end on one path.

1. Append to `STATUS.md`:
   - `- 04 complete at <timestamp> → see PLAN.md (N slices)`
   - Update `**Current step:**` to `05 — /vcf-framework:build (slice 1)`
   - Update `**Last completed:**` to `04`

2. Tell the user verbatim: "Step 04 (plan) complete for `<feature-slug>`. Plan has <N> slices. Run `/clear` then `/vcf-framework:build <feature-slug>` to start slice 1."
