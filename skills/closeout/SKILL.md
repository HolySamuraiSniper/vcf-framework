# /vcf-framework:closeout — Step 09: Docs, commit, ship, write back

**Goal:** Land the change cleanly **and** feed what you learned back into memory so the next loop starts ahead.

This is Step 09 of 10 in VCF gate mode — the final gate. For full doctrine, see `vcf-framework:overview`.

## Argument

Takes one argument: `<feature-slug>`.

## Prereqs

- `<cwd>/.vcf/<feature-slug>/FINAL-REVIEW.md` and `<cwd>/.vcf/<feature-slug>/VERIFY.md` must exist (outputs of `/vcf-framework:final-audit`).
- `STATUS.md` must show `**Last completed:** 08.5`.

If missing, **halt** and route the user back to `/vcf-framework:final-audit`.

## Inputs to read

- All `<cwd>/.vcf/<feature-slug>/*.md` artifacts — surprises, decisions, gotchas live across these
- `VERIFY.md` — goal-backward confirmation
- `FINAL-REVIEW.md` — any P2/P3 findings worth memorializing
- `git log` since loop start — for the WHY-not-WHAT commit messages

## Process

### 1. Update docs

- README / CHANGELOG / domain docs (CONTEXT.md, ADRs, glossary if vocabulary shifted)
- Anything that would make a teammate (or future-you) faster next time

### 2. Final atomic commits

Messages explain **why**, not **what**. Reference the PRD acceptance criteria each commit satisfies.

If `FINAL-REVIEW-FIX.md` already produced atomic commits for review fixes, don't re-commit those — they're already in.

### 3. Ship

Invoke whichever of these fits the repo:

- `Skill` tool with `skill: "superpowers:finishing-a-development-branch"` — for branch-finish flow
- `Skill` tool with `skill: "ship"` — gstack ship command (PR + checks)
- `Skill` tool with `skill: "land-and-deploy"` — gstack deploy flow

### 4. Memory write-back (mandatory — never skip)

Capture in persistent memory and vault:

**claude-mem** — usually auto-captured via session compaction. If a specific decision or surprise is worth indexing explicitly, add it via the claude-mem MCP tools.

**Obsidian vault wiki article** via `Skill: obsidian-cli`. Write to `~/Projects/joey-vault/wiki/<domain>/<feature-slug>.md` (or appropriate vault path for non-Joey work). Capture:

- **Surprises** — things that turned out different than expected
- **Decisions worth remembering** — especially the *why*
- **Gotchas for next loop** — what would have helped at `/vcf-framework:context`
- **New invariants or conventions established**

Then update `wiki/_index.md` and the domain index.

### 5. Slice-audit calibration (the meta-feedback step)

If `/vcf-framework:final-audit` caught issues that `/vcf-framework:slice-audit` (per-slice) missed, note the *kind* of issue here. Pattern: <what kind of bug>, <why slice-audit missed it>, <what would have caught it>. This is the feedback loop for the framework itself.

Most loops will have at least one of these. Skipping this section means the framework stops improving.

## Output

Write `<cwd>/.vcf/<feature-slug>/CLOSEOUT.md`:

```markdown
# Closeout: <feature-slug>

Generated by /vcf-framework:closeout at <ISO timestamp>.

## Shipped

- Final commits: <list of shas + one-line messages>
- PR / deploy URL: <link>
- Shipped at: <timestamp>

## Docs updated

- `README.md` — <what changed>
- `CHANGELOG.md` — <what changed>
- Other: ...

## Memory write-back

- Vault article: `wiki/<domain>/<feature-slug>.md`
- claude-mem entries: <ids if applicable>
- Updated indexes: `wiki/_index.md`, `wiki/<domain>/_index.md`

## Surprises

- ...

## Decisions worth remembering (with why)

- ...

## Gotchas for next loop

- ...

## New invariants / conventions established

- ...

## Slice-audit calibration

- **Pattern:** <kind of issue final-audit caught that per-slice missed>
- **Why per-slice missed it:** <reason>
- **What would have caught it earlier:** <reviewer scope change / additional check / etc.>
```

## Discipline

**Without write-back, every loop starts from zero. With write-back, the system compounds.**

The slice-audit calibration is what makes the framework improve over time. Skip it and you're just running a process; honor it and you're tuning the process.

## After this step

1. Update `STATUS.md`:
   - Append `- 09 complete at <timestamp> → CLOSEOUT.md. Loop closed.`
   - Update `**Current step:**` to `COMPLETE`
   - Update `**Last completed:**` to `09`
2. Tell the user verbatim: "Loop closed. `<feature-slug>` is shipped and written back. Start the next loop with `/clear` then `/vcf-framework:context <new-feature-slug>`."
